# 구매기획팀 Lv.5 에이전트 기획서 (샘플)

> slide-pack 변환 데모용 가상 기획서입니다. 인터뷰 6문항의 결과가 이렇게 정리되었다고 가정합니다.

## 1. 팀과 목적
- 구매기획팀 (팀장 1 + 팀원 2). 주간 자재 견적 비교·발주 품의 준비에 매주 약 6시간 소모.
- 에이전트 목적: 견적 취합 → 비교표 작성 → 품의 초안 생성을 자동화.

## 2. 에이전트 역할 정의
- 한 문장: "수신된 견적 메일을 읽어 비교표를 갱신하고 발주 품의 초안을 만든다."
- 하는 일: 견적 파싱, 비교표 기록, 품의 초안 작성
- 하지 않는 일: 발주 승인, 공급사와의 직접 소통

## 3. 데이터 명세
| 표 이름 | 칸 이름 | 원본 위치(SSOT) | 읽기/쓰기 |
|---|---|---|---|
| 견적비교표.xlsx | 공급사, 품목, 단가, 납기, 수신일 | 공용드라이브/구매기획/data | 쓰기 |
| 승인공급사목록.xlsx | 공급사, 등급, 담당자 | 공용드라이브/구매기획/data | 읽기 |

## 4. 대표 시나리오
- 트리거: 매주 월요일 09:00, 팀원이 지난주 견적 메일 폴더를 지정
- 입력: 견적메일(PDF 첨부 포함) → 처리: 파싱·승인공급사 대조 → 출력: 비교표 갱신 + 품의초안 + 재요청초안 + 확인브리핑
- 파이프라인: quote-parse → compare-update → weekly-draft → retry-request → confirm-brief

## 5. 결과물 반영 규칙
- 파싱 결과는 견적비교표.xlsx의 해당 품목 행에 기록
- 미승인 공급사 견적은 기록하지 않고 "검토 필요" 목록으로 분리

## 6. 연동 맵
- 현재는 독립. 차기: 발주 품의 초안을 결재 시스템 스킬로 전달 (md 형식)

## 6-1. 페르소나 인터뷰 반영 (2026-08 추가)
- retry-request: 예외 건(미승인·파싱 실패)의 후속 조치와 재요청초안 생성 — 실무자 인터뷰 발견 2
- confirm-brief: 팀장용 확인브리핑(지난주 대비 변경점·금액 근거·판단 포인트 요약) — 팀장 인터뷰 발견 1
- 근거: personas/ski-personas-interview.md (합성 인터뷰 — 실측 검증 전까지 가설)

## 7. 검증·휴먼인더루프 지점
- 확인브리핑(confirm-brief) 단계에서 팀장 확인 필수 — 금액이 걸린 문서이므로 사람이 최종 승인
- 단가가 직전 대비 ±15% 이상 변동 시 에이전트가 멈추고 확인 요청
