# 구매기획팀 통합 계약 (CONTRACT)

팀원이 각자 스킬을 만들기 **전에** 팀이 합의해 발급하는 인터페이스 계약이다.
개인은 skill.md의 본문을 자유롭게 쓰되, 아래 이름들은 문자열 그대로 지켜야 한다.

계약을 고쳐야 할 이유가 생기면 개인이 스킬을 고치지 말고 **이 파일을 먼저 고친다** (SSOT).

```contract
# 표 이름은 아래 철자가 정본이다. 띄어쓰기·언더스코어 변형 금지.
tables:
  견적비교표.xlsx: 공급사, 품목, 단가, 납기, 수신일
  승인공급사목록.xlsx: 공급사, 등급, 담당자

# 표마다 기록하는 스킬은 하나뿐이다. 나머지는 읽기만 한다.
writers:
  견적비교표.xlsx: compare-update

# 체인 순서. 앞 스킬의 outputs와 뒤 스킬의 inputs는 같은 단어를 쓴다.
chain: quote-parse -> compare-update -> weekly-draft -> retry-request -> confirm-brief

# 주고받는 페이로드 이름 (정본)
payloads: 견적메일, 파싱결과, 갱신된비교표, 품의초안, 검토필요목록, 재요청초안, 확인브리핑

# 정지 임계값. 모든 문서에서 이 형식으로만 적는다.
threshold: ±15%

# 휴먼인더루프 지점 — 이 스킬이 체인의 끝이며, 아무것도 자동 발송하지 않는다.
halt_at: confirm-brief
```

## 계약이 정하지 않는 것

- 스킬 본문의 서술 방식, 처리 로직의 세부, 예외 메시지 문구
- 스킬이 속할 사분면(depth/breadth/coil) — 통합 시 팀이 배치한다

## 위반 시 처리

`check_contract.py`가 제출된 스킬을 계약과 대조해 세 갈래로 분기한다.

| 판정 | 뜻 | 다음 단계 |
|---|---|---|
| 🟢 GREEN | 계약 준수 | 통합 점검기로 진행 |
| 🟡 YELLOW | 이름 표기 어긋남 (기계가 교정안 제시 가능) | 교정안 확인 후 반영, 재검사 |
| 🔴 RED | 팀의 결정이 필요한 충돌 | 팀이 계약 또는 담당을 정하고 재검사 |
