# 단일 SKILL.md Luna 실행 비교

## TL;DR

`gpt-5.6-luna`에 프로젝트 맥락을 주지 않고 `standalone-skill/SKILL.md` 하나만 전달해도 `result.md`와 9면 HTML 덱을 생성할 수 있었다. 1차는 375×667 한 화면이 24px 넘쳤다. 실브라우저 27면 측정을 강제한 2차는 27/27을 통과했지만, 독립 시각 리뷰가 흰 패널의 텍스트 대비와 모바일 표 충돌을 추가로 발견했다. 스킬에 대비·셀 충돌 검사를 보강하고 2차 결과물을 교정한 뒤 독립 재검토를 수행했다.

## 실험 조건

- 모델: `gpt-5.6-luna`
- 입력: 가상 제조업 초과근무 승인 감사 업무
- 허용 컨텍스트: `standalone-skill/SKILL.md`와 사용자 요청만
- 금지: 기존 A/B 결과, Jcurve 템플릿, 편집기 소스, 과거 Luna 결과 열람
- 출력: `result.md`, `presentation.html` 두 파일

## 무엇을 바꿨는가

1. 375×667, 768×720, 1280×720의 9화면, 총 27개 실브라우저 측정을 완료 조건으로 추가했다.
2. `scrollHeight`·`scrollWidth`가 client 크기를 1px 이상 넘으면 전체 검사를 다시 하도록 했다.
3. 375px에서 내부 스크롤 대신 문구 축약, 제목 축소, 표 재구성을 요구했다.
4. 흰 패널이 어두운 슬라이드에 놓일 때 계산 색상과 스크린샷을 확인하도록 했다.
5. 긴 식별자가 있는 모바일 표는 행 카드로 바꾸고 인접 셀 충돌을 검사하게 했다.
6. 실제 화면에 없는 선·범례를 주장하지 못하게 했다.

## 외부 공유 판단

단일 파일은 가상 데이터 워크숍, 초기 업무 구조화, HR 책임 경계 토론, 발표용 프로토타입에 충분하다. 실제 CSV 반복 처리, 결정론적 회귀, 승인 상태 영속화, 개인정보 런타임 차단, Jcurve L0–L4와 같은 기계 보증에는 부족하다.

운영 배포에서는 `SKILL.md`에 최소 스키마, 결정론적 실행기, 브라우저 QA를 함께 묶는 편이 안전하다.

## 반대 관점

단일 파일의 가벼움은 장점이다. 모든 사용처에 실행기와 검사기를 요구하면 공유 장벽이 높아진다. 따라서 단일 파일을 없애기보다 “프로토타입”과 “운영 패키지”를 명확히 분리하는 것이 현실적이다.
