# 일반화 Activity Packaging Coach 독립 실행 비교

## TL;DR

동일한 비식별 가상 구매 입력과 단일 `activity-packaging-coach/SKILL.md`를 서로 다른 독립 에이전트에 제공했다. 두 실행 모두 3개 독립 AI 업무를 하나의 `team agent`로 패키징하고 L0–L4를 통과했다. 기준 실행은 실제 Edge 27면에서 27/27이었고, Luna 원본은 375·768 화면은 통과했지만 1280 화면 9개 모두 문서 바깥쪽에 14px 세로 넘침이 있어 18/27이었다.

| 비교 항목 | 기준 독립 에이전트 | Luna 5 독립 실행 |
|---|---|---|
| 제공 입력 | 단일 일반화 SKILL + 동일 가상 구매 입력 | 단일 일반화 SKILL + 동일 가상 구매 입력 |
| 패키지 판정 | `team agent`, 독립 AI 업무 3개 | `team agent`, 독립 AI 업무 3개 |
| L0–L4 | PASS | PASS |
| 375×667 | 9/9 | 9/9 |
| 768×720 | 9/9 | 9/9 |
| 1280×720 | 9/9 | 0/9, 문서 세로 overflow 14px |
| 전체 화면 | 27/27 | 18/27 |
| 사람 정지점 | 입력 누락, 편차 검토, 구매자 확인, 외부 실행 | 동일 |
| 외부 실행 | 0 | 0 |

## 화면 관찰

- 두 결과 모두 9면 정보 구조, 한글 글리프, 카드·표·푸터, 사람 책임 구분은 읽을 수 있었다.
- 기준 결과는 좁은 화면 연결선, 긴 계약 식별자, 최소 글자 크기, focus-visible, reduced-motion까지 별도 회귀를 통과했다.
- Luna 원본의 375·768 화면은 카드 재배치와 한국어 줄바꿈이 안정적이었다.
- Luna 원본의 1280 화면은 활성 슬라이드 자체는 잘리지 않았지만, `body`의 바깥 패딩과 `min-height: 100vh`가 합쳐져 문서 높이가 viewport보다 14px 커졌다. 따라서 전체 페이지 fit 계약에는 실패다.
- Luna가 자체 보고서에서 적은 “375 브라우저 미실행”은 독립 Edge 재검사로 정정한다. 실제로는 375·768이 통과했고 1280만 실패했다.

## 결론과 변경 제안

1. 외부 공유 정본은 도메인명이나 HR 전용 필드를 갖지 않는 `activity-packaging-coach/SKILL.md`로 한다.
2. 공유 ZIP에는 세 SKILL을 중심으로 에이전트 정의와 최소 비식별 입력 예시를 넣는다. 이 둘은 모델이 실행 범위와 입출력 위치를 오해하지 않게 하므로 포함 가치가 있다.
3. 두 HTML 결과와 검증 요약은 비교용으로만 포함한다. Luna 원본은 실패 증거를 보존하기 위해 수정하지 않는다.
4. 생성 스킬에는 viewport fit을 활성 슬라이드뿐 아니라 `documentElement`에도 적용하고, 1280의 body padding까지 계산하도록 유지한다.

## 반대 관점

Luna 원본은 내용 전달과 워크숍 시연만 놓고 보면 충분히 쓸 수 있다. 보이지 않는 14px 페이지 스크롤 때문에 결과 전체를 폐기하는 것은 과도할 수 있다. 다만 이번 작업의 핵심이 “모양이 깨지지 않는 공유 결과”이므로, 최종 정본에는 수치형 fit과 사람의 화면 검토를 모두 통과한 기준 결과를 채택하고 Luna 결과는 비교 기준으로 남긴다.
