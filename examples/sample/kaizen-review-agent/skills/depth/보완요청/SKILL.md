# 보완요청

> 상류: 워크플로우 설계도 · Lv4 「개선과제」 · Lv5 「개선과제 발굴 및 심의」 · Lv6 「보완요청」
> Human 여부: 사람고유 · Skill화 용이성: 낮음

## 갈림길
이 태스크의 결과에 따라 다음이 갈린다: 효과정량화(루프백).
판단기준(원본 흐름도의 ◆): 보완된 제안은 효과 정량화부터 다시 돈다. A 또는 C로 판정되면 반복이 끝난다

## 되돌아가기 (루프백)
- 이 태스크에서 효과정량화(으)로 되돌아간다 — 근거가 보완되면 금액과 등급이 달라진다.
- 반복이 끝나는 조건: B 등급이 0건이 되면 끝난다.
- 5회차까지 B가 남으면 반복을 멈추고 사람에게 넘긴다 — 무한히 돌지 않는다.

## 판단기준
- 보완이 필요한 과제의 **목록과 사유(근거출처 미기재 / 효과 자료 없음)만** 만든다.
- **근거를 대신 만들지 않는다.** 보완은 제안자가 한다.
- 제안 내용을 고쳐 쓰지 않는다.

## 사람이 확인하고 멈추는 지점
- 보완요청 — 사람이 직접 판단한다. 자동으로 진행하지 않는다.
- 보완이 접수되었다고 사람이 알려주기 전에는 되돌아가지 않는다.
