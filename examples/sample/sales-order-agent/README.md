# 월간 수주·여신 심사 — 팀 에이전트 (갈림길 + 루프백)

**영업 사례**입니다. 재무(결산)·HR(성과평가) 팩과 같은 구조를 영업 업무로 옮겼습니다 —
갈림길에서 갈라지고, 물량을 조정하러 되돌아갔다가, 사람 앞에서 멈춥니다.

- 출처: **AX전략 워크샵 · 영업본부 석유제품영업팀** — 워크플로우 설계도에서 옮겼습니다.
- 원본 프로세스: **P-C3-1 월간 수주·여신 심사**
- 산출물 유형: **팀 에이전트 (갈림길·루프백 있음)** — AI 태스크 4개(ATF③) · 갈림길 1곳 + 루프백 1곳(ATF④)

## 흐름

```
판매계획확인[자동] → 주문접수취합[자동] → 공급가능확인[증강]
                                              ↑            ↓
                        ↩ 조정 후 재점검      │     여신한도점검[증강] ◆ 한도 초과 있음?
                        (한도초과 0이면 탈출)  │            │
                                              └────────────┼─ Yes → 여신조정요청[사람고유]
                                                           └─ No  → 수주확정품의[사람고유] ⛔
```

**루프백이 공급가능확인까지 되돌아가는 이유**: 여신 조정은 물량 축소로 이루어지므로,
물량이 줄면 제품별 공급 과부족도 함께 바뀝니다. 한쪽만 고쳐 다른 쪽이 깨지는 것을 막습니다.

## 돌려보기

```bash
python3 examples/sample/sales-order-agent/run.py
```

```
[판매계획확인] 제품 4종 · 진척 미달 2종 (경유, 휘발유)
[주문접수취합] 주문 11건 · 접수 9건 · 집계 제외 2건 (취소·보류)
[공급가능확인] [1회차] 제품 4종 · 공급 부족 1종 (등유 100kL)
[공급가능확인] 부족분을 어느 주문에서 뺄지 정하지 않음 — 배분은 사람이 함
[여신한도점검] [1회차] 거래처 6곳 · 한도초과 1곳 (동해상사) · 예외승인 1곳 (초과로 세지 않음)
◆ 한도 초과 있음? → Yes · 여신조정요청으로 분기
[여신조정요청] ⛔ 사람고유 — 초과 1곳의 목록과 근거만 만듦 (어느 주문을 얼마나 줄일지 정하지 않음)
    · 동해상사(C-104) — 한도 1,500,000,000 vs 합계 1,720,000,000 = 초과 220,000,000 (여유 70,000,000)
    ⏸ 영업담당 조정 대기 …
[여신조정요청] ↩ 공급가능확인으로 되돌아감 (탈출 조건: 한도초과 0)
[여신한도점검] [2회차] 거래처 6곳 · 한도초과 0곳
◆ 한도 초과 있음? → No · 수주확정품의로 진행 (2회차에 탈출)
[수주확정품의] ⛔ 사람고유 — 점검표 4건만 만들고 멈춤
```

## 지어내지 않는 것이 실행에서 보입니다

| 상황 | 에이전트가 한 일 |
|---|---|
| 취소 주문 1건 · 보류 주문 1건 | 집계에서 빼되 **표에서 지우지 않고** 점검표에 남김 |
| 여신 예외승인이 있는 거래처 (C-106) | 초과로 세지 않되 **승인 근거를 점검표에 남겨** 사람이 재확인 |
| 예외승인이 **없는** 초과 (C-104) | 사유를 지어내지 않고 그대로 조정 대상으로 올림 |
| 등유 공급 부족 100kL | 부족을 표시만 하고 **누구 물량을 줄일지 정하지 않음** |
| 할인·정산 조건이 데이터에 없음 | 기준단가로만 계산하고 **"실제 청구액과 다를 수 있다"고 명시** |
| 이번 달 주문이 없는 거래처 | 판정하지 않음 — 주문이 없는 것은 초과가 아님 |

## 실행 화면

`agent-mockup.html`을 브라우저로 엽니다. **▶ 실행**을 누르면 ● 시작부터 한 단계씩 돕니다.
하단 실행 로그가 흐르고, 진행 바가 0에서 100%까지 채워집니다.

1회차에서 갈라져 되돌아왔다가 2회차에 빠져나가는 장면이 그대로 재생되고,
**여신조정요청에서 멈춥니다** — 사람고유 지점이라 `확인하고 계속 ▶`을 눌러야 다음으로 갑니다.

숫자는 전부 `out/trace.json`에서 옵니다. 데이터를 고치고 `run.py`를 다시 돌린 뒤
`python3 check/make_mockup.py .`로 화면을 다시 만드십시오.

## 사람이 멈추는 자리

- **여신조정요청** — 영업담당이 조정을 확정할 때까지 멈춥니다.
  **어느 주문을 얼마나 줄일지 대신 정하지 않고, 여신 한도를 올려주지도 않습니다.**
- **수주확정품의** — 영업본부장이 점검표를 확인할 때까지 멈춥니다.
  **수주 확정·출하 지시 코드가 이 팩에 없습니다.**

## 데이터

`data/수주데이터.md` **한 파일**에 표 6개가 들어 있습니다. 전부 **실습용 가상 값**이고,
거래처명·여신한도·주문·재고 모두 실재하지 않습니다.
실도입 전에 SAP SD·MM·여신관리시스템 데이터로 교체합니다.

표마다 왜 그 값인지가 문장으로 붙어 있습니다. 값을 고쳐서 다시 돌려보십시오:

| 고칠 것 | 일어나는 일 |
|---|---|
| 거래처마스터의 `C-104` 여신한도 → `2000000000` | 초과가 사라져 **루프백 없이 1회차에 수주확정품의** |
| 재고생산의 등유 생산예정 `200` → `300` | 공급 부족이 사라져 점검표 **4건 → 3건** |
| 여신예외승인에서 `C-106` 줄 삭제 | 초과가 **2곳**(동해상사·신흥유통)이 됨. 표가 비면 '해당 없음'으로 보고 계속 돕니다 |
| 주문접수의 `O-2609-011` 상태 `보류` → `접수` | 접수 10건이 되고 **광명주유도 한도를 넘어** 조정 대상이 2곳으로 늘어남 |
