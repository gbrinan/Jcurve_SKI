# 통합 계약 (워크플로우 설계도 변환 초안)

Lv4 「실적관리」 · Lv5 「월간 실적 마감 및 경영보고」의 Lv6 태스크 5개를 이었다. 갈림길이 있어 경로가 2개다.
루프백: 소명요청검토 ↩ 편차분석 (탈출: 소명을 반영해 편차를 다시 산출한다. 임계 초과 항목이 0이 되면 반복이 끝난다)

```contract
tables:
  실적데이터.md: 사업부제출 / 월간실적 / 편차임계 / 소명접수 / 보고서양식 (5개 표)
  실적취합결과.md: 사업부코드, 사업부명, 제출여부, 제출일, 항목수, 상태
  편차분석결과.md: 사업부코드, 사업부명, 항목, 계획, 실적, 편차, 편차율, 임계율, 판정
  경영보고서초안.md: 순번, 절 이름, 필수, 상태, 근거
writers:
  실적취합결과.md: 사업부실적취합
  편차분석결과.md: 편차분석
  경영보고서초안.md: 경영보고서작성
chain: 사업부실적취합 -> 편차분석 -> 소명요청검토; 사업부실적취합 -> 편차분석 -> 경영보고서작성 -> CEO보고상정
payloads: 월간실적마감및경영보고입력, 사업부실적취합결과, 편차분석결과, 소명요청검토결과, 경영보고서작성결과, CEO보고상정결과
threshold: 편차 임계 매출 10% · 영업이익 15% (절대값 기준, 전 사업부 동일)
halt_at: 소명요청검토, CEO보고상정
```

## 갈림길 조건 (편차분석)

| 조건 | 다음 |
|---|---|
| 편차율 절대값이 임계율을 넘는 항목이 1건 이상 | 소명요청검토 (→ 소명 반영 후 편차분석으로 되돌아감) |
| 임계초과 0건 | 경영보고서작성 |

편차율 = (실적 − 계획) ÷ |계획|. 미제출 사업부와 실적이 빈 항목은 계산하지 않는다 —
**실적이 0인 것과 모르는 것은 다르다.**
임계 기준은 `편차임계` 표 하나뿐이다 (PP-5 [DEC] 사업부마다 다르던 기준을 통일).

## 루프백 (소명요청검토 ↩ 편차분석)

원본 Agent 3이 **L3(소명) 루프백**으로 기록한 자리다.

- 탈출 조건: 소명을 반영해 재산출했을 때 **임계초과가 0**
- 사람이 `인정`한 소명만 초과에서 뺀다. 소명이 없거나 `미인정`이면 초과로 남는다 —
  **소명을 지어내지 않는다.**
- 5회차까지 초과가 남으면 반복을 멈추고 사람에게 넘긴다. 소명이 없거나 인정되지 않은
  항목은 스킬이 해소할 수 없다 — 무한히 돌지 않는다.
