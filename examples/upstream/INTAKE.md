## 스킬별 한 줄

1. **주요뉴스검색** (김도희, 증강): 당일 구독 메일에서 프로젝트·지역·경쟁사 관련 기사를 골라 중요도 순 뉴스 목록을 만든다.
2. **브리핑초안작성** (박성준, 증강): 뉴스 목록을 기사당 두 문장으로 요약해 출처를 붙인 브리핑 초안을 OneDrive에 저장한다.
3. **배포전검토** (김다혜, 사람고유): 초안에서 수치·회사명 문장에 확인 표시를 달고 팀장 앞 검토 요청 메일 초안을 만든 뒤, 발송은 팀장이 정한다.

## 확인표 C: 실행 순서

```
주요뉴스검색 → 브리핑초안작성 → 배포전검토 → [팀장 확인에서 멈춤]
   └ 웹 뉴스 검색(예외 분기, 오늘 실행 불가)
```

- 스킬 사이 연결은 설계도에 없습니다. 스킬 2의 첫 노드 입력과 스킬 1의 마지막 노드 출력이 같은 말("뉴스 목록")이라 이었고, 스킬 3도 같은 방법("OneDrive 초안")으로 이었습니다. **인터뷰에서 확인할 자리 2곳.**
- ATF는 ④순서 가변성을 "미충족(순서가 매번 같음)"으로 판정했습니다. 갈림길 없는 직선이면 산출물 유형은 "팀 스킬팩(순차 실행)"입니다.

## 의도 제안

3개 스킬이 같은 업무("정세 브리핑 초안 작성 › 전황 업데이트")를 한 줄로 잇습니다. 입출력이 겹치는 쌍이 없어 **통폐합 후보는 0쌍**이고, 곧바로 워크플로우 엮기(`weave`)로 가면 됩니다. 정지 지점은 배포전검토의 팀장 확인 하나이며, ATF도 ⑥검증 가능성을 "미확인(틀렸을 때 누가 보는지 미정)"으로 두었으니 계약의 `halt_at`에 이것을 적으면 조건이 풀립니다. 이대로 진행할까요?

## 인터뷰(askflow)에서 물을 것: `(없음)`·`(추정)` 목록

1. 데이터 정의: 표가 하나도 없습니다. 구독 메일 수신함·OneDrive 지정 폴더가 실제로 무엇인지(메일함 이름, 폴더 경로), 뉴스 목록·브리핑 초안이 파일로 남는지, 남는다면 이름과 칸.
2. 스킬 사이 연결 2곳(위 추정)이 맞는지, 뉴스 목록과 초안이 어떤 형식으로 넘어가는지(페이로드 정본 이름).
3. 팀 정체성: 주당 5시간(ATF `hoursPerWeek`) 외에 팀 미션과 주기(매일 아침).
4. 연동: "여러사람_공유만"(ATF `wrap`)이 다른 에이전트와의 연동을 뜻하는지, 공유 채널이 무엇인지.
5. 웹 뉴스 검색 분기: 권한이 생기면 자동으로 켤지, 계속 사람이 수기로 할지.
6. 사분면: 세 스킬 모두 한 번에 끝나는 일로 보여 `depth/`로 두되, 매일 아침 반복이므로 팩 전체를 `coil/`로 볼지.
